# My Anime Library

Личная коллекция аниме с простым тёмным интерфейсом: постеры и кнопка «+». React + TypeScript + Vite, Tailwind CSS, Motion for React, Lucide.

[Открыть сайт](https://ahsoka1tano.github.io/My-Anime-Library/)

## Запуск

Нужен **Node.js 22.12+**. Рекомендуется актуальная LTS-версия Node.js.

```sh
npm install
npm run dev
```

Откройте адрес, который напечатает Vite (обычно `http://127.0.0.1:5173`). В Windows можно запустить `start.ps1` из PowerShell: скрипт также умеет использовать Node.js и pnpm из установленного окружения Codex, если npm отсутствует в PATH.

Проект содержит `pnpm-lock.yaml`. Для воспроизводимой установки с pnpm:

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Разрешён только необходимый install-скрипт esbuild в `pnpm-workspace.yaml`.

## Возможности

- При первом запуске — только «+» по центру экрана. Нажатие открывает поиск. После добавления на экране остаются постеры и плитка «+», без шапки, баннера, подписей и счётчиков.
- Поиск на английском и японском через **AniList GraphQL**, на русском через **Shikimori GraphQL**. Ключи API не нужны. Запрос и название аниме передаются соответствующему каталогу; отзывы и оценки остаются в браузере.
- Debounce 550 мс, отмена устаревших запросов, очередь с интервалом 1,1 с, кеш на 5 минут и ограниченная повторная попытка при HTTP 429. Ошибки, отсутствие результатов и медленный ответ отображаются явно. Выдуманных результатов при ошибке нет.
- Добавление с защитой от дублей по **MyAnimeList ID** — одному идентификатору для обоих каталогов.
- Статусы «Хочу посмотреть», «Смотрю», «Просмотрено» доступны внутри карточки. Постеры на главной располагаются по дате добавления, начиная с новых.
- Изменение прогресса кнопками и вводом числа, оценка 1–10 с очисткой, свободный отзыв и автоматическое сохранение.
- Просмотренное аниме получает полный известный прогресс. Возврат в «Смотрю» сохраняет его и позволяет уменьшить. Переход в планы обнуляет прогресс. Оценка и отзыв сохраняются при любых переходах. Для неизвестного количества серий можно хранить текущий прогресс, без выдуманного общего числа.
- Shared layout для постера, обратное раскрытие, уважение `prefers-reduced-motion`, lazy loading и заглушки постеров.
- Модальные окна на нативном `<dialog>`: фокус остаётся внутри окна, Escape и клик по фону закрывают окно, затем фокус возвращается к исходному элементу.
- Удаление с подтверждением внутри карточки. Иконки импорта и экспорта JSON находятся в окне поиска, которое открывается через «+»; импорт показывает предварительный просмотр.

## Хранение и резервные копии

Все личные данные находятся в `localStorage`, ключ `my-anime-library:v1`. Формат:

```json
{
  "version": 1,
  "entries": []
}
```

Экспорт содержит метаданные аниме, ID MyAnimeList, статус, прогресс, оценку, отзыв, даты добавления и изменения. Импорт проверяет версию, все поля, URL изображений, даты, диапазоны, согласованность статуса и прогресса и отсутствие дублей. Максимальный размер импортируемого файла — 5 МБ; максимум 5000 записей. Ошибка в одной записи отклоняет весь файл до изменения коллекции.

Импорт **объединяет** коллекции: отсутствующие записи добавляются; при совпадении ID остаётся запись с более поздним `updatedAt`. Подтверждение показывает число новых историй. Пустой импорт не очищает коллекцию.

При повреждённом локальном формате оригинал не перезаписывается: экспорт позволяет скачать исходные данные, затем можно восстановиться импортом резервной копии. Если браузер запретил запись или закончилось место, изменения остаются в памяти текущей страницы и появляется предупреждение с экспортом.

Коллекция общая для одного профиля браузера и одного origin (протокол + домен + порт). **Синхронизации между устройствами и аккаунтов нет.** На другом порту или домене будет другая локальная коллекция. Переносите данные через JSON. Очистка данных браузера удалит коллекцию. Не редактируйте одну коллекцию одновременно в нескольких вкладках: автоматическое согласование вкладок пока не реализовано.

Без доступа к API сохранённые записи, оценки и отзывы продолжают работать при открытом приложении. Постеры, которые браузер не закешировал, требуют интернета; при ошибке появится заглушка. Полноценная установка PWA и запуск сайта с нуля офлайн пока не реализованы.

Внешний каталог может отдавать оригинальные или английские названия и описания. Русский поиск получает русские названия и описания из Shikimori; интерфейс приложения русскоязычный.

## Структура

```text
src/
  components/          AnimeGrid, AnimeCard, AnimeDetails, AnimeSearch,
                       StatusSelector, RatingSelector, EpisodeProgress,
                       Modal, Poster
  lib/api.ts           Каталоги, нормализация, кеш, очередь, обработка ошибок
  lib/storage.ts       Repository, валидация, сериализация и объединение
  lib/library.test.ts  Тесты прогресса, статусов и сохранности данных
  types.ts             Общая модель и независимая логика переходов статусов
  App.tsx              Состояние коллекции и композиция экранов
  styles.css           Тема и адаптивные стили
public/
  favicon.svg          Иконка приложения
```

В UI используется единая нормализованная модель `Anime`/`LibraryEntry`. Для будущих аккаунтов и Supabase можно сохранить компоненты и модель: заменить `LibraryRepository` и вынести загрузку и очередь асинхронного сохранения из App в хук. На этом этапе repository синхронный, поскольку localStorage синхронный. Персональные оценки не смешиваются с рейтингом каталога.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run preview
```

Опционально `npm run check:api` проверяет настоящие поисковые запросы обоих каталогов; нужен интернет. Этот скрипт не читает личную коллекцию.

`build` включает TypeScript и создаёт `dist/`. Vitest проверяет границы эпизодов, переходы статусов, сохранение личных данных, round-trip JSON, недопустимые поля, неизвестные версии, дубли, атомарное отклонение повреждённого файла и объединение по дате.

## Публикация

Приложение статическое. Перед публикацией выполните проверки и `npm run build`, затем загрузите **содержимое `dist/`** на статический хостинг. Для Vercel/Netlify: команда сборки `npm run build`, каталог публикации `dist`. Переменные окружения не требуются.

GitHub Pages публикуется автоматически после push в `main`. Workflow `.github/workflows/deploy.yml` устанавливает зависимости по lock-файлу, запускает ESLint и тесты, проверяет TypeScript при сборке и публикует `dist`. Его также можно запустить вручную через Actions → «Проверка и публикация сайта» → Run workflow. В настройках Pages источником должен быть выбран GitHub Actions.

Адрес сайта: [ahsoka1tano.github.io/My-Anime-Library](https://ahsoka1tano.github.io/My-Anime-Library/). `base: './'` поддерживает размещение в подпапке репозитория. Роутер не используется, поэтому перенаправления на `index.html` не нужны. Открывать `dist/index.html` через `file://` не следует — используйте HTTP-сервер. Локальный `npm run build` сам ничего не публикует и не отправляет в Git.

На опубликованном сайте коллекция хранится отдельно от локального запуска. Для переноса откройте «+», экспортируйте JSON из локальной версии и импортируйте его на сайте.
